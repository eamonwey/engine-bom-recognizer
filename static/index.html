配置工作环境

先连接视觉模型，再按需要配置企业导出格式、图纸要求和变更关联。

企业字段与标注要求 按需配置

让导出的 BOM 使用企业列名，并告诉模型需要关注哪些参数和标注要求。

例如：将“件号”导出为“物料编码”；对指定零件检查热处理标注。

配置文件需要哪些内容？

使用 JSON 文件，包含 export_fields（字段映射）、parameter_dictionary（参数词典）和 required_annotations（标注规则）。规则须注明适用条件和依据。项目 examples 目录提供示例。

企业关联索引 影响分析使用

告诉系统哪些文档、零件、工序和检验项目彼此关联，变更时才能找到受影响的对象。

材料规范变更 → 关联 BOM → 加工工序 → 检验项目

配置文件需要哪些内容？

导入 JSON 对象清单，填写唯一 ID、对象类型、匹配关键词和依赖关系。depends_on 表示该对象依赖的上游对象。缺少索引时，系统会提示无法判定影响。

视觉模型 API 接入

填写后点「保存设置」即可全局生效，各功能页的「模型」下拉框选“默认配置”就走这里。
内网部署（约束 C-01/C-02）：Base URL 指向内网 vLLM 服务（如 http://10.0.0.5:8000/v1），模型名填服务加载的开源模型（Qwen2.5-VL / InternVL 等），数据不出厂区。

各功能页如何选用模型

「BOM 与图纸纠错 / 文档要素与复核」页面上各有一个「模型」下拉框：
· 默认配置 = 用本页设置的模型　· 离线演示(Mock) = 不花钱跑固定示例数据　· 视觉模型 API = 强制走真实模型
命令行/批量实验的密钥仍可用服务端环境变量 VISION_API_KEY 提供（优先级低于本页保存的值）。

开始使用工艺智能工作台

第一次使用，先在系统设置连接支持图像输入的模型。

  1. 生成 BOM 与检查图纸

    上传二维图纸，核对清单和问题候选，保存后导出。

  2. 提取技术文档要素

    上传文档，定位原文，逐项确认参数、材料、工艺和检验要求。

  3. 分析版本变化

    上传前后两个版本；配置企业关联索引后，可继续追踪影响范围。

  4. 完成正式审核

    编辑稿保存不等于批准。到“复核与历史”，使用独立身份完成编制、复核和批准。

详细说明书位于项目 docs/USER_MANUAL.md。离线演示使用固定示例，不能验证真实图纸准确率。
