# ERR-03/04/05/07/09/10 专项检查改进与验证

日期：2026-10-11。当前视觉模型：qwen3.7-flash。

## 已实现的变化

新增专项事实提取、确定性检查和可追溯结果展示。网页的BOM联合识别和独立审图接口使用同一套配置与规则；企业配置不再只传给其中一个入口。

默认流程：原图和局部放大 → 专项事实JSON → 页码/引用/证据/类型校验与有限重试 → 规则计算 → 视觉审图补充 → 人工复核。

原始整页保留在前，最多对前两页附加四象限放大。放大块有原页及坐标映射，不能作为新页或新增事实。每条观察有ID、来源页、原文、位置、可读状态及可选坐标。未知零件编号可以保留null，不能据此强行建立跨视图对应关系。

| 编号 | 本次新增能力 | 明确限制 |
|---|---|---|
| ERR-03 公差 | 解析对称±、斜杠表示的上下偏差、极限尺寸和部分ISO公差代号；检测负±幅值、上下偏差颠倒；按孔轴极限区间计算最小/最大间隙及配合类别；核对图上明确的配合意图和孔轴代号大小写 | 未注公差不当零公差。代号只有语法解析，数值查表必须导入有来源表。尚无完整GB/T公差表及一般公差覆盖，统计尺寸链未实现 |
| ERR-04 形位公差 | 框格数值、按项目区分基准需要、已识别基准引用、同要素自引用、部分要素类型不匹配；支持共同基准A-B；空格不当复杂修饰符 | 形状公差无需一律加基准；位置度/轮廓度可有无基准情形。没有识别到基准不等于原图缺失。复杂框格、修饰符和完整GPS条款尚不覆盖 |
| ERR-05 视图 | 同零件/分区、同要素、不同视图、明确对应的尺寸和孔数比较；单位归一；半径/直径/线性类型分别处理 | 不比较不同零件的同名孔，不从像素长度反推尺寸，不把投影缩短或隐藏情况直接判错；未做三维重建及视图充分性认证 |
| ERR-07 标准件 | 有来源标准状态快照、部分标准件类别矛盾、可导入允许规格表；非正数紧固件规格；明确安装空间的尺寸区间比较 | 未收录标准显示无法确认，旧标准引用须按图纸/合同日期核实。盲孔必须确认有效伸入长度，通孔不按全螺钉长度直接判错。尚无完整紧固件标准库 |
| ERR-09 技术要求 | 明确适用的企业规则与原文匹配，未找到时提示核实提取完整性；占位文本、硬度范围颠倒、负Ra；标准引用状态 | 不默认所有件都要热处理/涂层/检验。按零件和页码限制匹配，跨页归属不能确认时待核实。尚不验证完整工艺可行性 |
| ERR-10 格式 | 比例正数与企业允许比例列表，多视图比例；原始PDF页面框物理尺寸、A0–A4识别与企业允许图幅；图片明确提示无法判物理图幅 | 加长图幅、裁切或缩放不自动判错。PDF页面框不是CAD原始图幅认证。字体、线宽、线型、CAD图层和实际绘图比例尚不覆盖 |

计算使用Decimal。算术成立仍依赖视觉模型读取和对应关系正确，因此所有问题均为待工程师复核，`compliance=not_certified`。

未被专项规则确认的六类模型判断保存在`unverified_findings`，不计为已验证错误。模型引用专项finding_id补充证据时，保留程序原来的计算描述和原文，不允许模型覆写数值。检查状态checked表示具体规则已执行，不能推导全图合格。

## 标准来源与可追溯范围

内置的是2026-10-11核查的状态元数据快照，不是完整条文或实时标准库。数据在`engine_bom/standards_snapshot.json`。

- [GB/T 1182-2018官方状态及替代关系](https://std.samr.gov.cn/gb/search/gbDetailed?id=7643B2F25130267CE05397BE0A0AAF6A)：该版本及其代替的2008版。
- [GB/T 70.1-2008官方状态及替代关系](https://std.samr.gov.cn/gb/search/gbDetailed?id=71F772D7F825D3A7E05397BE0A0AB82A)：该版本及其代替的2000版；官方标题支持内六角圆柱头螺钉类别核对，不支持凭空生成完整规格表。
- [GB/T 1800.2官方版本状态清单](https://openstd.samr.gov.cn/bzgk/std/std_list?p.p1=0&p.p2=GB%2FT1800.2&p.p90=circulation_date&p.p91=desc)：2020和2009版本状态。没有从网页标题推导极限偏差数值。
- [GB/T 14690-1993官方信息](https://std.samr.gov.cn/gb/search/gbDetailedCNF?id=71F772D7889FD3A7E05397BE0A0AB82A)：比例标准元数据；本次比例规则为正数算术和企业列表，并未宣称实现完整标准比例条款。
- [NIST形位公差资料](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=910523)：有限项目及基准关系的工程参考，不能替代GB/T 1182全条款认证。

## 企业配置

在“系统设置 → 企业字段与标注要求”导入JSON。参考`examples/inspection-rules.example.json`。它是演示配置，实际使用前需替换规则依据和适用范围；本次没有自动导入它改变企业要求。

`inspection_rules`仅允许以下字段，不能借企业配置覆盖检查开关或来源页：

- `format_policy`：source、allowed_scales、allowed_sheets。图幅列表当前仅A0–A4，未配置列表时不作企业允许列表判断。
- `standards`：reference、status（current/replaced）、source、checked_on，replaced另需replacement。可选allowed_specifications、incompatible_name_terms。来源字符串只是导入的审计依据，导入前仍需核准数据。
- `tolerance_bands`：band、min_exclusive、max_inclusive、lower_mm、upper_mm、source。所有数值为mm，基本尺寸区间为下界不含、上界包含；重复/重叠区间、非有限值、倒置区间及缺来源拒绝。

`required_annotations`仍使用id、requirement、source、applies_when，新增可选match_terms。没有匹配词时仅供模型/人工观察，不执行“缺失”的确定性匹配。两个规则ID不能重复。

命令：

```powershell
python -X utf8 -m unittest discover -s tests -q
python -X utf8 scripts/test_review_fix_browser.py
```

浏览器测试通过：原有编辑、版本、审计和装配保存回归，以及专项问题、标准快照、检查计数、展开证据和脚本文本转义；没有JS运行错误。

真实API联测使用qwen3.7-flash。测试脚本先从图片提取标题栏、尺寸和BOM，再执行专项提取及混合审查；设计答案仅在运行后评分，没有将expected.json传入模型。云端测试覆盖审图链路，不是整套BOM装配/人工批准流程的重新验收。

2. ERR-04：垂直度框格基准格为空；图外基准A存在也不能填补框格缺失引用。

4. ERR-07：GB/T 70.1-2000被有来源快照标为已由2008版替代，须核实适用日期。
5. ERR-09：热处理“待定”，以及硬度HRC 60～55上下限颠倒，共两条规则。

早期失败运行保留在121232、121626、122006三个结果目录，未删除或计入最终通过率。它们暴露了未知编号导致整份失败、模板遗漏证据、模型将“可比较”误解为“读数一致”、框格空白误处理等问题。最终增加独立事实阶段、完整字段模板、局部放大、可比较排除理由和空格处理后通过。最后核查不仅看ERR编号，还检查对应规则，避免用错误原因碰巧命中同一编号。

## 如何在网页审查

代码已经保存，但本次自动审批审查拒绝了停止旧服务和启动新版服务两项操作，工具仅返回“blocked by policy”。本次没有启动8789；原8788服务仍是修改前已加载的后端，需要手动重启才能使用新检查逻辑。关闭旧服务后，在项目目录运行：

```powershell
python -u -X utf8 -m engine_bom.webapp --host 127.0.0.1 --port 8788
```

如果旧服务在可见终端运行，用Ctrl+C停止。若它是隐藏后台进程，先核对占用8788的PID属于本项目Python服务，再通过任务管理器结束对应进程。当前任务注册表仍在内存，普通重启会使此前任务不再出现在列表；源文件、result.json和复核日志不因此删除。本次未实现通用任务恢复，不宣称这一缺口已修复。

1. 刷新页面后，在“BOM与图纸纠错”上传`data/acceptance/engineering_checks_20261011/E02_defects.png`，使用默认真实视觉模型。
2. 查看“图纸检查结果”，逐项核对上述六类。结果可能有其他类别候选，需单独对照原图。
3. 展开“审图覆盖、专项规则与计算证据”，看具体规则、来源页、原文、计算记录及标准快照日期。
4. 特别检查ERR-03的0.01/0.05mm、ERR-04的空基准格、ERR-05的20/21，以及ERR-09的两项技术要求问题。
5. 再上传E01_clean.png，这六类不应出现已验证问题。不能因此认为该简化测试图满足全部生产规范。
6. 未确认观察、依据不足和API失败不能当“已通过”。确认提取和适用条件后再人工修订与复核。

## 主要源码

- `engine_bom/engineering_checks.py`：专项事实合同、配置、数值及六类规则。
- `engine_bom/hybrid_inspection.py`：独立事实Agent loop、局部放大、规则与视觉补充、未确认判断的分流。
- `engine_bom/enterprise.py`：配置导入校验。
- `engine_bom/webapp.py`：两个审图入口统一配置和PDF元数据。
- `engine_bom/titleblock.py`、`drawing_layout.py`：尺寸所属零件范围、标题栏原始页码映射。
- `engine_bom/inspect_rules.py`：避免不同零件同名尺寸误关联。
- `static/app.js`：专项规则、覆盖计数、证据及计算显示。
- `tests/test_engineering_checks.py`、`scripts/test_review_fix_browser.py`：回归。
- `scripts/test_engineering_inspection.py`：可复现开发数据和真实API联测。

后续重点仍是独立真实数据验收、完整标准及企业知识库、复杂GPS/几何关系、CAD字体/线型/图层读取，以及端侧模型部署。
