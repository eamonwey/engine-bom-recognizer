## 5. 已确认问题与建议优先级

### F-01：标题栏材料错位（P1，结果准确性）

证据：真实结果 `title_block.material=""`、`material_applicable=false`、`extra.title_no_field="45"`，而预期材料为 45。错误已在后端结构化结果存在，因此不是前端把正确材料显示错位置。

定位：`engine_bom/titleblock.py` 的提取提示词和归一化流程；图纸局部裁剪、字段标签对齐也应一并核对。当前证据不足以把根因唯一归结为裁剪。

建议：按标题栏标签提取并保留证据位置；增加材料标签与自定义序号字段冲突校验；对“assembly 所以材料不适用”的推断增加图面优先约束。修复后用不同标题栏版式真实复测，不能只补这一张图的特例。

### F-02：非法 options 导致永远运行的任务（P2，任务完整性）

复现：向 `/api/jobs/bom` 上传正常 PNG，同时令 multipart 字段 `options` 为 `{invalid`。收到 HTTP 400，随后 `/api/jobs` 中仍存在状态 running 的任务 `20260923191209-d7cfe6`。

定位：`engine_bom/webapp.py:664` 起，先 `_create_job`、保存文件，再 `json.loads(options)`；解析异常时未进入异步任务收尾。与“缺失文件”测试不同，这是有效 multipart 和有效文件下的参数错误。

建议：先验证参数，再创建任务；或统一异常路径将已建任务标记 failed 并记录原因。补充非字典 options、缺失 compare 第二个文件等同类边界测试。

### F-03：尺寸修订建议含未证实的工程假设（P2，建议质量）

证据：真实 ERR-01 建议提出改为 50+50 或增加未标注间隙。系统保留待复核状态，也没有自动改图，但用户可能误把模型假设当作已验证设计依据。

定位：`engine_bom/hybrid_inspection.py` 的 VLM 提示与问题融合，以及 `engine_bom/dimension_chains.py` 的尺寸链输出。算术矛盾与设计修正方案需分别表达。

建议：保留“40+50≠100”这一可计算结论；设计意图不明时只要求核实，不给出无依据的具体尺寸/结构修正。

### F-04：界面状态提示仍可改善（P3）

- `static/extensions.js:52` 区域定位提示写成“正在定位”，完成后的状态需要明确更新。本轮通过源码确认，未新增真实区域结果的浏览器复现。
- 无选框修订错误显示在页面上部，用户在下方修订区可能不易看见；建议错误就近显示并将焦点移到提示。
- Mock 结果区域仍使用普通“识别结果”标题；虽然设置、侧栏和指南说明固定示例，建议结果上方也明显标记“演示数据，与上传内容无关”。

以上为本次发现与观察，不等同全面不存在其他缺陷。本轮交付是测试及报告，没有把上述缺陷暗中修改后再称原版本全部通过。

## 6. 数据集与真值审查

本地外部 manifest 记录 30 份 enginuity 参考样本，固定来源版本 `c079c44f602c227109793cf2fdb3919ea8a99331`；30 份状态全部为 `pending_two_independent_humans`。另有 40 份人工构造纠错样本，其 manifest 未提供统一 review_status 字段。

70 份资源可访问、哈希/清单校验通过，只能证明测试资源完整，**不能证明标签已成为独立人工真值**。外部 manifest 自身说明上游标签由模型生成，并保留来源及适用场景限制。本轮依据本地清单检查，没有重新在线审计上游数据。

因此报告不提供“70 份真实模型准确率”。需要先完成独立标注、争议裁决，再固定测试集跑真实模型，分别统计 BOM 行 P/R/F1、端到端字段准确率、文档完全正确率，以及按错误类别统计审图漏检/误报。

## 7. 尚未充分验证的边界

- 新一轮真实 API 连接、额度失败恢复、真实模型多次运行稳定性与批量精度。
- 端侧视觉模型部署、显存、吞吐、内网运行及离线时的实际效果。
- DXF / DWG 渲染依赖，复杂 CAD 文件；大页数、大图片、长时间高并发及中途强制退出。
- 多浏览器、手机尺寸、完整无障碍键盘流程、下载文件在 Excel/Word 原生程序中的显示效果。
- 修订文字的字形、位置及图线遮挡的逐像素验收；当前确认的是副本、哈希、格式与审计。
- 任务重启恢复：源码任务注册表是进程内 `_jobs`；磁盘有 result.json 不代表重启后接口一定自动恢复。需要专门持久化恢复测试。
- 公差、配合、形位、工艺可制造性、标准适用条件及装配干涉，不能仅凭 VLM 覆盖声明认定已完成审查。
- UI 各项按钮并非全部做了真实浏览器点击；保存/审核/配置等写入路径主要通过隔离 HTTP 验证，表中已区分。

## 8. 复跑与人工审查方法

在项目目录运行：

```powershell
python -X utf8 scripts/comprehensive_test.py --serve
```

脚本打印新的 `REPORT_DIR`，使用 8790；该端口需空闲。新开终端，将下面路径替换为新目录：

```powershell
python -X utf8 scripts/supplemental_test.py data/test_runs/20260923_190929
python -X utf8 scripts/smoke_validation_review.py http://127.0.0.1:8790
```

补充测试预期会复现 F-02，因此不能只看主脚本 summary.json。测试脚本当前把失败写入 JSON，进程退出码不能替代结果审查。`--serve` 会持续运行，在测试终端按 Ctrl+C 结束。独立数据保留便于复核。

人工审查重点：

1. 对照 `expected.json`、原 PNG、`real_model_review.json`，特别核查标题栏材料 45、数量 0 与安装要求 4，以及尺寸链 40+50≠100。
2. 在隔离网页选择 Mock 验证操作流程，注意固定示例不是原图识别结果。
3. 打开 `supplemental_results.json` 核对 F-02 失败及任务编号，再查对应隔离日志。
4. 检查两个角色不能共用身份完成三级批准、篡改内容不能沿用旧审批。对应 HTTP 测试已保留预期与实际状态。
5. 最后完成独立人工真值审查，再开展真实模型批量验收；不要用 Mock 通过数代替算法能力指标。
