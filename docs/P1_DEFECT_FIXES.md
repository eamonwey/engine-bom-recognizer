# P1 代码缺陷修复（2026-09-21）

本次按用户确认修复代码中的高优先级缺陷，不是新增需求表P1功能。

| 缺陷 | 触发及后果 | 修复 |
|---|---|---|
| 同名版本相互覆盖 | 新旧版本都叫 drawing.pdf 时，后上传覆盖先上传，可能错误报告无变更 | 按上传字段分目录保存，保留各自原始文件名 |
| 复核/批准内容错配 | 页面编辑了待审JSON，非提交操作却不发送它，服务端只检查版本号并批准旧快照 | 前端发送当前内容；后端验证内容指纹与待审快照相同，缺失或不符则拒绝 |
| 并发日志丢失 | 多线程同时读改写日志；复现120条仅剩4条 | 整个读改写加锁，临时文件完整写入后原子替换；保证同一服务进程内多线程一致性 |
| 损坏日志被清空 | JSON解析失败后当空数组处理，下一次保存覆盖旧记录 | 明确报错并保留原文件；替换失败同样保留旧文件 |
| 人工保存未同步任务文件 | 文档与装配编辑只更新内存/另存文件，result.json仍是旧结果 | 更新任务文件后发布内存状态；编辑操作串行化；失败不发布新内存结果 |

审核接口兼容性变化：review、approve、reject 都必须携带所审阅的完整 payload；旧客户端漏传时返回400，刷新网页使用新脚本后再操作。普通编辑稿保存不等于正式批准。

验证：
- 修改前运行 tests.test_p1_integrity，5个复现测试全部失败。
- 新增8项回归测试，覆盖同名版本、快照不符/缺失、并发日志、损坏日志、持久化及磁盘失败。
- 全量129项测试通过；static/app.js、static/extensions.js通过node语法检查。
- 没有调用云端模型；本轮不涉及真实图纸准确率评测。
