## 1. P1：带文字层的 PDF 会漏掉图片中的变更

- 位置：`engine_bom/changedetect.py:37-44`，`engine_bom/document_layout.py:15-23`。
- 触发：PDF 有可提取的标题文字，同时实际图纸或参数位于扫描图片中；仅图片发生变化。
- 复现：生成两个 PDF，共用相同文字标题，嵌入的图片分别写有 `BOLT QUANTITY: 4` 与 `BOLT QUANTITY: 8`。`extract_text` 只取得标题，`align_and_diff` 返回空列表，即 0 项变化。
- 原因：只检查整份文件是否完全没有文字；只要有标题或页码，就绕过了扫描文件保护。图像块被排除，比较阶段也没有视觉/OCR补充或覆盖不足标记。纯矢量图形变化也不在文字比较范围内。
- 影响：变更清单、影响分析和 ECN 都可能建立在漏检结果上。
- 修复建议：逐页、逐区域确认比较覆盖；对图片/图形区域进行视觉或栅格差异检查。尚未支持时明确返回“比较不完整”，不能将文字相同表示为整份图纸无变化。

## 2. P1：BOM 编辑日志不能还原修改过程

- 位置：`engine_bom/webapp.py:840-848`。
- 触发：同一 BOM 连续保存多次编辑稿，没有另行提交正式审核快照。
- 复现：数量 `1 → 2 → 3`；日志仅记文档 ID、行数、编辑者、备注、时间；编辑稿文件仅剩数量 3。日志无旧值、新值或不可变版本引用，无法恢复中间的数量 2。
- 原因：编辑稿按相同文件名覆盖，日志未保存字段差异或完整版本。
- 影响：日常人工修正无法完整追溯，也无法可靠整理用于模型迭代的修正数据。正式三角色审核快照独立存在，但不会自动覆盖每次编辑稿保存。
- 修复建议：每次保存追加不可变快照或字段级 before/after 差异，绑定 job ID、来源文件指纹、版本和操作者；将落盘与日志写入作为同一事务。

## 3. P1：BOM 保存与导出采用不同校验口径

- 位置：`engine_bom/webapp.py:829-831,856-857`；转换丢弃警告在 `engine_bom/webapp.py:478-480`；导出调用在 `engine_bom/webapp.py:906`。
- 触发：在数量字段填写 1.5。当前 schema 将数量定义为整数。
- 复现：保存成功；JSON 数量为 1.5；CSV/Excel 使用的转换结果为 null；汇总数量为 0。
- 原因：保存接口只检查 components 是对象数组，原始值直接落盘；汇总和表格导出重新执行类型转换，转换警告又被丢弃。
- 影响：用户看见保存成功，但不同导出格式给出不同数据，数量可能无声变空。
- 修复建议：保存前统一进行字段类型及业务校验；不合法的人工输入直接提示具体行列。若业务允许小数数量，统一修改 schema、汇总和所有导出格式，不可仅单个接口接受。

## 4. P2：BOM 保存后，前端旧装配树仍可再次提交

- 位置：`static/app.js:204-212`；`static/extensions.js:8-11`；`engine_bom/webapp.py:808-812`。
- 触发：先有零件 A 的装配关系，再把同一 BOM 行改为 B 并保存，然后点击保存装配层级。
- 复现：后端第一次正确标记 `invalidated_by_bom_edit`；再次提交旧树后变成 `reviewed`，当前件号已经是 B，证据仍是 A 的原始说明。
- 原因：BOM 保存成功后仅显示提示，没有刷新/清空装配表格与 JSON 编辑器；层级提交也没有绑定 BOM 版本或指纹。旧树仍满足索引范围和结构校验。
- 影响：旧关系可能误用于新零件。操作仍需用户点击保存，所以低于前三项自动漏检或数据不一致问题。
- 修复建议：BOM 保存响应返回更新后的状态，前端同步清空旧树并提示重建；层级提交携带 BOM revision/hash，服务端拒绝过期关系。
