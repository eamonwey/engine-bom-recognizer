本轮为实现增量，不能据此认定需求表所有 P0 已验收。自动测试是程序逻辑验证，不是识别准确率。真实图纸新功能尚未做模型复测。

## 你怎么审查

1. 打开 http://127.0.0.1:8788/ ，刷新页面。上传一张有真实装配父子关系的图纸，查看“装配层级”，逐条对照证据。演示 Mock 不产生虚构装配树，应显示未识别关系。
2. 修改层级JSON：把某节点的父节点设为自己，保存必须拒绝；改为有依据的关系后保存，下载Excel检查“装配层级”工作表。
3. 在“系统设置”导入 examples/impact-index.example.json。此文件纯演示，不是真实企业数据、也不是真值。对比两个TXT：旧版“材料 TC4”、新版“材料 TC11”。应显示规范→BOM→工序→检验的依赖路径。未导入任何索引时应显示“未配置”，不能解释为无影响。
4. 上传长文档，检查末尾参数仍被抽取；点击“定位原文”，核对页码、区域或原文块。DOCX没有可靠分页，系统不猜页码。
5. 导入 examples/enterprise-profile.example.json，仅用于验证映射；真实使用前替换规则来源与适用条件。在设置页导出当前BOM企业JSON/CSV/Excel。
6. 管理员在项目目录分别运行下面三条命令，为三位不同人员创建身份。命令只在本机显示各自令牌，不要把令牌放在聊天、截图或Git里。生产环境请用真实用户名。

```powershell
python scripts/provision_reviewer.py --user author --role editor
python scripts/provision_reviewer.py --user checker --role reviewer
python scripts/provision_reviewer.py --user approver --role approver
```

7. “复核与历史”载入当前BOM或文档，编制人提交；复核人加载同一编号核对快照后复核；批准人再加载批准。编制令牌不能批准。重新编辑提交后，旧批准不得沿用。页面内普通“保存”是编辑稿保存，不等于正式批准。
8. 执行 `python -X utf8 -m unittest discover -s tests -v`。新测试在 tests/test_p0_assembly_impact.py；本轮121项通过，包含HTTP保存/导出/权限检查。DXF测试需要 requirements-cad.txt。

## 尚未达到完整 P0 验收的项

- 原生 DWG、旧 DOC 尚未接通；需本地合法转换器或先导出 PDF/DOCX。DXF中的外部参照、字体和复杂布局需真实CAD样本验收。
- OCR/标题栏/明细表/参数抽取等百分比指标、100页30秒、每文件3秒没有达标证据；现在的云端VLM串行调用也不能承诺这些时延。
- 跨页表格自动合并、跨版本语义/章节级对齐仍不完整；扫描版本对比会明确要求先OCR，而非静默生成“无变更”。
- 全量企业模板、ERP/PLM真实接口、企业标准有效性库、细粒度缺漏标注和跨视图尺寸关联需继续接入。企业标注规则目前提供给VLM形成候选发现，尚非完备的确定性规则引擎。
- 文档逐项复核已接通；批量复核、覆盖整个应用的账号权限与生产认证尚未完成。目前角色限制适用于正式审核快照流程。
- 装配层级80%、错误检出率、影响分析覆盖率必须使用独立人工标注数据测量；示例关联索引不能作为验收真值。
- 端侧模型部署、量化、硬件性能验收未完成。
