## 1. 文档目的

本说明书用于指导用户安装、启动和使用“发动机元器件 BOM 智能识别系统”。系统接收工程图纸、技术文档及其不同版本，提供以下能力：

1. 从 PDF、图片或 DXF 图纸中提取标题栏和明细栏，生成结构化 BOM。
2. 基于规则和视觉语言模型生成图纸问题候选项。
3. 从技术、工艺文件中提取技术参数、材料、工艺要求和检验要求。
4. 对比两个文档版本，识别新增、删除和修改内容。
5. 根据企业关联索引分析变更可能影响的 BOM、工序、检验项、产品和文档。
6. 支持人工编辑、原文定位、装配层级确认以及编制—复核—批准流程。
7. 导出 JSON、CSV、Excel 和 ECN Markdown 草稿。

本系统输出是工程辅助结果。模型识别、图纸问题候选项、装配层级和变更影响都需要具备相应资质的人员复核。未经人工批准的输出不能直接作为生产、放行或设计更改依据。

## 2. 系统工作流程

```text
图纸或技术文件
      │
      ├─ 图纸 → 预处理 → VLM识别 → BOM/标题栏/尺寸/问题候选
      │                              │
      │                              ├─ 人工编辑BOM
      │                              ├─ 确认装配层级
      │                              └─ 生成文字修订副本
      │
      ├─ 技术文档 → 版面解析 → 要素提取 → 原文定位 → 逐项确认/驳回
      │
      └─ 两版文档 → 段落对齐 → 变更分类 → 关联影响分析 → ECN草稿

编辑结果 → 编制提交 → 独立复核 → 独立批准 → 版本化审核记录
```

## 3. 用户角色

| 角色 | 主要工作 | 不能替代的工作 |
|---|---|---|
| 普通操作员 | 上传文件、运行识别、查看和导出结果 | 不能把模型输出直接视为批准结果 |
| 编制人员 `editor` | 修正数据并提交不可变审核快照 | 不能复核或批准自己提交的快照 |
| 复核人员 `reviewer` | 核对原图/原文与快照，复核通过或退回 | 不能修改后直接复核；修改须退回编制 |
| 批准人员 `approver` | 对已复核且内容指纹一致的快照批准 | 不能批准自己编制或复核的记录 |
| 系统管理员 | 安装、启动、模型配置、用户令牌、企业配置和备份 | 不负责替代工艺判断 |

“确认复核结果”按钮保存的是编辑稿和人工修正记录；“批准”才表示三角色工作流中的正式批准状态。

## 4. 支持的输入与输出

### 4.1 图纸 BOM

| 类型 | 支持情况 | 说明 |
|---|---|---|
| PDF | 支持 | 每页渲染为图像后识别；二维页面最可靠 |
| PNG/JPG/JPEG/BMP/TIF/TIFF/WEBP | 支持 | 单张图片作为一页图纸 |
| DXF | 有条件支持 | 需要安装 `requirements-cad.txt`；渲染纸空间或模型空间后识别 |
| DWG | 暂不原生支持 | 请先在可信内网工具中转换为二维 PDF、DXF 或图片 |
| 仅含交互式 3D 的 PDF | 不支持 | 请从 CAD 导出可见二维页面 |

标准 BOM 可导出 JSON、CSV、Excel；Excel 中包含 BOM 工作表，存在装配层级时还包含“装配层级”工作表。

### 4.2 技术/工艺文档

支持 `.docx`、`.pdf`、`.txt`、`.md`、`.png`、`.jpg`、`.jpeg`。不支持旧版 `.doc`，请先转换为 `.docx` 或 PDF。

提取结果包含四类：

- 技术参数：参数名、数值、单位、适用条件、来源。
- 材料要求：材料名称、牌号、规格、标准、热处理/表面处理。
- 工艺要求：内容、类型、位置。
- 检验要求：检验项目、方法、验收标准、引用标准。

可导出 JSON 和 Excel。

### 4.3 版本对比

支持 `.docx`、`.pdf`、`.txt`、`.md`。扫描 PDF 没有可提取文本时，系统会提示先完成 OCR，不会把空文本错误地解释为“没有变更”。

```powershell
Get-NetTCPConnection -LocalPort 8788 -State Listen |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

确认进程确实是本系统后再关闭：

```powershell
Get-NetTCPConnection -LocalPort 8788 -State Listen |
  ForEach-Object { Stop-Process -Id $_.OwningProcess }
```

## 7. 首次配置视觉模型

打开左侧“系统设置”，找到“视觉模型 API 接入”。

### 7.1 Provider

- `mock`：离线演示，返回固定示例结果，不验证真实图纸准确率，也不消耗 API 额度。
- `openai_compat`：调用 OpenAI 兼容接口，适用于阿里百炼兼容模式或内网 vLLM 等服务。

### 7.2 配置项

| 配置项 | 含义 | 示例 |
|---|---|---|
| Base URL | 兼容接口根地址 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 模型名 | 服务端实际提供的视觉模型 ID | 以供应商控制台列出的模型为准 |
| API Key | 调用密钥 | 仅在本地设置页输入，不要写入聊天或截图 |

操作步骤：

1. 选择 `openai_compat`。
2. 填写 Base URL、模型名和 API Key。
3. 单击“测试连接”。该操作会产生一次很短的真实 API 请求，可能产生少量费用。
4. 确认连接成功后单击“保存设置”。
5. 回到业务页面，模型下拉框选择“默认配置”。

保存后的网页配置位于 `data/web_settings.json`。API Key 不会显示在状态接口中，但文件本身含有配置值；应限制该文件的操作系统访问权限，并确保它不进入 Git、邮件或共享盘。

也可在启动服务前使用环境变量：

```powershell
$env:VISION_BASE_URL="你的兼容接口地址"
$env:VISION_MODEL="模型ID"
$env:VISION_API_KEY="你的密钥"
python -X utf8 -m engine_bom.webapp --host 127.0.0.1 --port 8788
```

若网页设置中已经保存 API Key，网页配置的优先级高于环境变量。单击“清除已保存的 Key”只删除网页保存值，不会清除环境变量。

## 8. BOM 与图纸纠错

### 8.1 运行识别

1. 打开“BOM 与图纸纠错”。
2. 单击上传区域或拖入 PDF、图片或 DXF。
3. 选择模型：
   - 默认配置：使用系统设置中的模型。
   - 离线演示 Mock：检查页面流程，不代表真实识别。
   - 视觉模型 API：强制使用已配置的真实模型。
4. 根据原图质量选择预处理：
   - 倾斜校正：扫描页有轻微旋转时开启。
   - 去噪：有扫描噪点时开启，处理时间更长。
   - 二值化：灰底或对比度较差时尝试；细线较淡时应比较开启前后的效果。
5. 单击“生成 BOM 并检查图纸”。高密度、多页图纸可能需要数分钟。

一次任务会尝试生成标题栏、BOM、装配层级候选、图纸区域、尺寸标注以及图纸问题候选。部分模型调用失败时，页面可能仍保留已经成功的 BOM，但会显示相应功能未完成。

### 8.2 查看标题栏

标题栏结果用于检查图号、名称、材料、设计/审核信息等。字段缺失可能有两种原因：原图确实没有该字段，或模型未正确读取。应通过原图定位确认后再判定为图纸问题。

### 8.3 编辑和保存 BOM

零部件表中可编辑的常用字段包括件号、名称、规格、材料、数量、单位、装配位置、供应商和备注。

建议逐行核对：

1. 序号与图面引出序号是否对应。
2. 图号、件号和名称是否逐字一致。
3. 标准件的规格是否被保留。
4. 数量是否表示图纸中的真实数量。
5. 材料和单位是否误串行。
6. 来源页是否合理。

编辑完成后单击“确认复核结果”。该操作保存编辑稿；如果 BOM 内容发生变化，原装配层级会自动失效，因为 `component_index` 可能已经变化。此时必须重新确认装配层级。

### 8.4 理解图纸检查结果

图纸检查由两部分组成：

- `origin=rule`：确定性规则基于已抽取的标题栏、BOM、尺寸和引出序号运行。
- `origin=vlm`：视觉模型根据图面生成的问题候选。

当前规则重点覆盖：

- ERR-01：有稳定要素标识时的跨位置尺寸数值矛盾。
- ERR-06：材料为空或疑似不规范。
- ERR-08：标题栏/明细栏必填项、序号、数量、重复件号、引出序号对应问题。

视觉模型还可能给出 ERR-02/03/04/05/07/09/10 候选项，但这些不等同于已由几何或标准数据库证明的错误。所有问题都应检查页码、位置、证据和建议；没有问题也不代表完成了全部工程审图。

### 8.5 确认装配层级

装配层级节点表示一次装配出现，同一零件在不同父项下可建立多个节点。系统不会为了凑足层级而自动把未知关系设为顶层。

最小节点示例：

```json
{
  "nodes": [
    {
      "id": "root-1",
      "component_index": 0,
      "parent_id": null,
      "quantity_per_parent": 1,
      "evidence": "装配图总成引出序号1",
      "source_page": 1
    },
    {
      "id": "child-1",
      "component_index": 1,
      "parent_id": "root-1",
      "quantity_per_parent": 4,
      "evidence": "局部装配视图显示4件连接到序号1",
      "source_page": 1
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | 本次装配出现的唯一节点 ID |
| `component_index` | BOM 表从 0 开始的行号，不是图纸序号 |
| `parent_id` | 父节点 ID；有图面证据的顶层节点填 `null` |
| `quantity_per_parent` | 每一个父件所需数量；未知时填 `null` |
| `evidence` | 支持该关系的图面证据，不能为空 |
| `source_page` | 证据所在页，1 起始 |

系统会拒绝重复节点、循环关系、不存在的父节点、无证据关系、非法数量和超范围页码。填写复核人后单击“保存已确认层级”。存在未覆盖 BOM 行时，状态为部分复核。

### 8.6 图纸区域定位

区域定位按钮可能包含标题栏、明细栏、技术要求、视图和图框。单击按钮会打开对应页并绘制区域框。区域只是定位辅助；应检查框是否覆盖了真正的目标区域。

2026-10-11 更新：模型先给出粗框，程序在原页上跟踪与框内相连的图面线条，尝试补齐被截断的轮廓。按钮显示“已补边（待复核）”或“范围待调整”。相邻区域、孤立标注或超出搜索范围的轮廓可能仍未覆盖，状态不等于工程合格。

定位后进入“调整蓝框查看范围”模式，拖动可重画蓝框。此调整只影响当前查看，不保存到识别结果；重新定位会恢复自动范围。要改文字，先单击“框选文字修订范围”，重新拖动形成红框。蓝框不能提交文字修订。

### 8.6.1 一维装配公差链

展开“审图覆盖、专项规则与计算证据”，查看“一维装配公差链”中的组成环原文、增减方向、极限范围、允许范围和超差余量。模型读取尺寸、功能要求和端点，程序按同一装配分区的唯一连续端点路径计算；证据不够时显示依据不足，不凭尺寸数值凑关系。

例如腔体 L=100±0.1 mm、内件 B=90±0.1 mm，间隙 S=L−B 的范围是 9.8～10.2 mm。要求 S=10±0.1 mm 时，提示 ERR-01“可能超差”：部分极限组合超出允许的9.9～10.1 mm，并非每件都一定超差。要求10±0.3 mm时，计算范围满足该要求，但尺寸对应关系仍需人工复核。

未注公差、单位不明、端点不连续、装配分区不明或多个候选路径时，不能得出通过结论。当前仅支持有明确上下偏差或极限尺寸的一维水平/竖直线性链，不自动套用一般公差，不做统计/RSS、二维/三维、形位公差或选择装配分析。尺寸抽取连续三次校验失败时不输入错误尺寸，页面明确提示重新识别或人工核实。

### 8.7 生成图纸修订副本

此功能只在 PDF 或图片上覆盖指定区域中的文字，不修改 CAD 几何、尺寸约束或原始设计模型。

操作步骤：

1. 选择页码并单击“显示原图”。
2. 单击“框选文字修订范围”，在预览图上拖动形成红框，框选需要替换的文字。框选应略大于旧文字，但不能覆盖邻近线条或尺寸。
3. 填写复核人、原文字和确认后的新文字。
4. 单击“按已复核内容生成修订”。
5. 打开修订图纸，逐页比较原图与副本。

系统生成新文件，不覆盖原件，并记录输入/输出 SHA-256、复核人、时间和补丁列表。PDF 中框选区域会先被删除再写入新文字；图片输出统一为 PNG。旋转 PDF 页、错误页码、无效框或文字无法装入框时会拒绝生成。

批量修订 JSON 示例：

```json
{
  "reviewer": "张三",
  "patches": [
    {
      "approved": true,
      "source_page": 1,
      "bbox": [0.70, 0.82, 0.91, 0.88],
      "old_text": "TC4",
      "new_text": "TC11",
      "expected_source_sha256": "识别结果中记录的原文件哈希"
    }
  ]
}
```

`bbox` 使用整页归一化坐标 `[x0,y0,x1,y1]`，每个值在 0 到 1 之间。

### 8.8 导出

- JSON：保留完整结构、模型信息、验证问题和装配层级，适合系统对接和审计。
- CSV：UTF-8 BOM 编码，适合 Excel 打开和扁平 BOM 导入。
- Excel：BOM 为主工作表；已识别或复核的装配树位于“装配层级”工作表。

应先保存编辑稿，再导出；否则导出的是识别任务的当前状态。

## 9. 文档要素与复核

### 9.1 提取步骤

1. 打开“文档要素与复核”。
2. 上传支持的文档。
3. 选择模型并单击“开始提取”。
4. 等待四类结果出现。
5. 点击每一项的“定位原文”：
   - PDF 文本或扫描页：显示原页并标出模型提供的区域。
   - DOCX/TXT/MD：显示对应原文块；DOCX 没有可靠分页时不会猜测页码。
6. 直接编辑错误字段，并将状态设为“确认”或“驳回”。
7. 单击“确认复核结果”保存编辑稿。
8. 导出 JSON 或 Excel。

长文档会按原文块分段处理，避免只识别文档开头。状态为 `partial` 或出现“结果不完整”警告时，表示一个或多个分段没有通过输出校验，必须回看原文补录。

## 10. 变更与影响分析

### 10.1 对比步骤

1. 打开“变更与影响分析”。
2. 左侧上传变更前版本，右侧上传变更后版本；两者文件名可以相同，系统会分开保存。
3. 保持“忽略纯格式变化”可排除空白变化；若需要审查排版变化则取消勾选。
4. 单击“开始对比”。
5. 查看新增、删除、修改数量和分类。
6. 使用筛选器只查看某类变化。
7. 核对变更前后文字和页码/原文块位置。
8. 如已配置企业关联索引，继续核对影响对象、严重度和依赖路径。
9. 单击“生成变更单（ECN）草稿”下载 Markdown 草稿。

系统当前使用段落级对齐和规则分类。段落大幅重写、表格拆分合并、扫描件 OCR 误差和复杂章节重排仍可能产生漏配或误配。

### 10.2 变更分类

预定义分类包括技术参数修改、材料替换、工艺调整、标准更新、格式/排版修改、错别字/措辞修改及其他。当前分类主要依赖关键词规则，必须人工修正不合理分类。

### 10.3 影响分析的含义

影响分析只覆盖已经导入的企业对象、关键词、标识符和依赖关系。页面显示“未配置”表示没有企业关联索引，不能解释为“没有影响”。

`depends_on` 表示当前对象依赖哪些上游对象。例如检验项依赖工序、工序依赖 BOM；当 BOM 相关内容变化时，系统沿反向关系找到工序和检验项。

严重度是候选评估：索引对象标记 `critical: true` 时显示高，否则当前实现通常显示中。最终影响程度需工程师确认。

## 11. 复核与历史

### 11.1 数据集与验收审查

“数据集审查台”用于比较外部图纸、人工参考标签、模型预测和纠错样本。只有经过独立人工确认的标注才能作为 Ground Truth。公开数据、示例 JSON 或模型自身输出都不能自动视为真值。

### 11.2 管理员创建三类用户

在项目根目录分别执行，例如：

```powershell
python scripts/provision_reviewer.py --user author --role editor
python scripts/provision_reviewer.py --user checker --role reviewer
python scripts/provision_reviewer.py --user approver --role approver
```

每条命令会显示一次个人令牌。系统只保存令牌哈希，无法从文件恢复原令牌。应通过组织批准的私密渠道交给本人，不要发到群聊、截图、Git 或普通文档。

### 11.3 正式审核流程

#### 编制提交

1. 先在 BOM 或文档页面完成编辑并保存编辑稿。
2. 打开“复核与历史”。
3. 单击“载入当前 BOM”或“载入当前文档要素”。
4. 填写编制人员令牌。
5. 检查文档/任务编号和 JSON 快照。
6. 单击“编制提交”。

#### 复核

1. 复核人员填写相同的文档/任务编号及自己的令牌。
2. 单击“加载版本”。
3. 对照原图或原文核查完整快照。
4. 内容正确时单击“复核通过”；需要修改时单击“退回”。

复核人员不能在文本框中修改内容后直接通过。服务端会比较完整内容指纹；任何修改都必须由编制人员重新提交。

#### 批准

1. 批准人员加载同一编号的已复核版本。
2. 使用自己的批准令牌。
3. 再次核对内容指纹和审核轨迹。
4. 单击“批准”。

编制、复核、批准必须由不同用户完成。重新提交新内容会清除旧复核人和批准人，旧批准不会自动沿用到新版本。

### 11.4 状态含义

| 状态 | 含义 |
|---|---|
| `draft` | 尚未正式提交 |
| `submitted` | 编制已提交，等待复核 |
| `reviewed` | 已复核，等待批准 |
| `rejected` | 已退回，需要编制重新提交 |
| `approved` | 当前内容指纹对应的版本已批准 |

### 11.5 记录页面

- 人工修正记录：BOM、文档、装配层级等保存动作。
- 变更历史：版本对比和 ECN 生成记录。
- 正式审核快照与轨迹：保存在 SQLite 审核库中；不能用普通修正记录替代。

## 12. 企业字段与标注要求

该功能对应 ERP/PLM 字段适配、企业参数词典和企业标注规则。示例文件位于 `examples/enterprise-profile.example.json`，仅用于验证格式，不是企业正式标准。

示例结构：

```json
{
  "version": "enterprise-2026-01",
  "export_fields": {
    "part_number": "物料编码",
    "name_zh": "物料名称",
    "quantity": "数量",
    "material": "材料牌号"
  },
  "required_annotations": [
    {
      "id": "RULE-HT-01",
      "requirement": "适用零件必须注明热处理要求",
      "source": "企业制图规范 Q/ABC 001-2026 第5.2条",
      "applies_when": "零件设计要求热处理时"
    }
  ],
  "parameter_dictionary": ["尺寸", "公差", "硬度", "粗糙度", "转速"]
}
```

字段说明：

- `version`：企业配置版本，建议与受控文件版本一致。
- `export_fields`：系统 BOM 字段到企业列名的映射；列名不能重复。
- `required_annotations`：每条规则必须有 ID、要求、依据和适用条件。
- `parameter_dictionary`：文档抽取时优先关注的术语，不允许模型据此猜造数值。

导入后对下一次任务生效。完成 BOM 识别后，可在设置页导出企业 JSON、CSV 或 Excel。上线前必须用真实 ERP/PLM 模板进行试导入并核对字段类型、必填项、编码、数量精度和层级关系。

## 13. 企业关联索引

该索引用于变更影响分析。示例位于 `examples/impact-index.example.json`，纯属演示。

```json
{
  "objects": [
    {
      "id": "SPEC-TC4",
      "name": "TC4材料规范",
      "kind": "document",
      "keywords": ["TC4"],
      "identifiers": ["Q/ABC-MAT-004"],
      "source": "受控文件库路径或编号"
    },
    {
      "id": "BOM-1001",
      "name": "一级转子BOM",
      "kind": "bom",
      "depends_on": ["SPEC-TC4"]
    },
    {
      "id": "OP-20",
      "name": "热处理工序",
      "kind": "process",
      "depends_on": ["BOM-1001"],
      "critical": true
    }
  ]
}
```

允许的 `kind`：`document`、`bom`、`process`、`inspection`、`product`。

管理要求：

1. 每个对象 ID 必须唯一且稳定。
2. `depends_on` 中的 ID 必须在同一文件存在。
3. 关键词应足够具体，避免用“材料”“尺寸”等宽泛词造成大量误报。
4. `source` 应指向可追溯的受控来源。
5. 产品/BOM/工艺变更后应同步维护索引并更新版本记录。

## 15. REST API 对接要点

主要端点：

| 方法 | 地址 | 用途 |
|---|---|---|
| POST | `/api/jobs/bom` | 上传图纸并创建异步 BOM 任务 |
| POST | `/api/jobs/doc` | 上传文档并创建要素提取任务 |
| POST | `/api/jobs/compare` | 上传前后版本并创建对比任务 |
| GET | `/api/jobs/<id>` | 查询任务状态和结果 |
| POST | `/api/bom/save` | 保存人工编辑的 BOM |
| POST | `/api/doc/save` | 保存人工编辑的文档要素 |
| POST | `/api/assembly/save` | 保存人工确认的装配层级 |
| POST | `/api/reviews/transition` | 提交、复核、退回或批准快照 |
| GET | `/api/export/bom/<id>?fmt=json|csv|xlsx` | 导出 BOM |
| GET | `/api/export/doc/<id>?fmt=json|xlsx` | 导出文档要素 |
| GET | `/api/compare/<id>/ecn.md` | 下载 ECN 草稿 |
| GET | `/api/history` | 查询变更历史 |
| GET | `/api/reviewlog` | 查询人工修正记录 |
| GET | `/api/status` | 查询模型和预处理状态，不返回密钥 |

POST 请求必须包含 `X-API-Token`。网页会自动使用启动时嵌入页面的会话令牌。外部系统对接时，应在启动服务前配置稳定令牌：

```powershell
$env:ENGINE_BOM_API_TOKEN="由管理员生成的高强度随机令牌"
python -X utf8 -m engine_bom.webapp --host 0.0.0.0 --port 8788
```

正式审核接口还需要个人 `X-Review-Token`。外部系统应遵守异步任务模式：创建任务后按合理间隔轮询 `/api/jobs/<id>`，直到状态为 `done` 或 `failed`。

当前 GET 端点未统一要求 API Token。生产部署必须依靠可信内网边界、反向代理鉴权或后续统一鉴权改造，不能直接暴露到互联网。

## 16. 数据目录、保留和备份

| 路径 | 内容 | 建议 |
|---|---|---|
| `data/web_settings.json` | 网页模型配置，可能含 API Key | 严格限制权限，不入 Git |
| `data/web_jobs/` | 上传原件、任务结果、修订副本 | 按数据分级管理和定期备份/清理 |
| `data/reviewed/` | 人工保存的 BOM、文档和装配层级 | 纳入受控备份 |
| `data/review_log.json` | 人工修正记录 | 保留并监控损坏 |
| `data/change_history.json` | 版本对比与 ECN 历史 | 纳入变更审计 |
| `data/reviews.sqlite` | 正式快照、版本状态和审核轨迹 | 重点备份；迁移时一并复制 |
| `data/review_users.json` | 用户 ID、角色和令牌哈希 | 严格限制权限，不包含明文令牌 |
| `data/knowledge/associations.json` | 企业关联索引 | 按企业知识库流程受控维护 |
| `data/predictions*/` | 命令行或实验预测 | 与对应配置、模型版本一同留存 |

默认单次 HTTP 请求上限为 100 MB，已完成任务默认保留 24 小时，内存最多保留 200 个任务。可用以下环境变量调整：

```powershell
$env:ENGINE_BOM_MAX_UPLOAD_MB="100"
$env:ENGINE_BOM_JOB_TTL_HOURS="24"
$env:ENGINE_BOM_MAX_JOBS="200"
```

任务过期清理不应替代组织的数据归档制度。需要长期留存的结果应在到期前导出或纳入备份。

## 17. 准确率评测与 Ground Truth

准确率必须使用独立人工标注的参考数据测量。建议流程：

1. 选取具有代表性的真实图纸，并完成脱敏和使用授权。
2. 由至少两名工程人员独立标注 BOM、标题栏、装配层级和错误项。
3. 对分歧进行仲裁，形成锁定版本的 Ground Truth。
4. 将图纸放到 `data/raw/`，同名标注 JSON 放到 `data/annotations/`。
5. 固定模型、提示词、配置、数据集版本和运行时间。
6. 执行实验或评测命令。
7. 查看精确率、召回率、F1、字段准确率、完全正确率、漏检和误报明细。

模型输出、公开图纸本身、系统示例、从图纸自动生成的标签都不自动构成 Ground Truth。装配层级准确率和图纸错误检出率需要单独定义匹配规则与人工标注协议。

## 18. 常见问题与处理

### 18.1 网页打不开

1. 检查运行服务的 PowerShell 窗口是否仍在。
2. 检查地址和端口是否一致。
3. 执行：

```powershell
Get-NetTCPConnection -LocalPort 8788 -State Listen
```

无输出表示 8788 没有服务监听。重新启动服务。

### 18.2 端口已被占用

查出 `OwningProcess` 并确认进程身份；关闭旧服务，或改用其他端口：

```powershell
python -X utf8 -m engine_bom.webapp --host 127.0.0.1 --port 8789
```

### 18.3 页面显示“服务未连接”

检查服务是否重启、浏览器是否仍打开旧端口，以及终端是否有异常堆栈。修改后端后仅刷新页面不足以加载新代码。

### 18.4 API Key 已设置但模型调用失败

依次检查 Base URL、模型 ID、额度、密钥权限、网络代理和接口是否支持图像输入。先在设置页运行“测试连接”；连接测试成功不代表图像任务一定成功。

常见状态：

- 401/403：密钥错误或无权限。
- 404：Base URL 或模型名不正确。
- 429：额度、速率或并发限制。
- 超时：图片过大、页面过多或模型服务繁忙。

### 18.5 预处理显示不可用

安装 `opencv-python` 并重启服务。对于清晰的电子 PDF，不必强制开启二值化和去噪。

### 18.6 Excel 下载失败或为空

安装 `openpyxl` 并重启服务。先确认任务状态为完成，且页面中已有可导出的结果。

### 18.7 DXF 无法读取

安装 `requirements-cad.txt`。若仍失败，检查外部参照、字体和复杂布局；必要时由 CAD 软件导出受控二维 PDF 后上传。DWG 不能直接当 DXF 使用。

### 18.8 识别结果为空

检查是否误选 Mock、图纸分辨率、明细栏是否可见、模型是否支持视觉输入以及 API 是否返回被截断内容。尝试只开启倾斜校正或提高 PDF DPI后重新运行，但应保留原配置和结果用于比较。

### 18.9 视觉审图未完成

表示视觉模型调用或输出校验没有完成。当前规则结果仍可能显示，但不代表完成了全量审图。检查任务中的 `visual_status` 和服务日志。

### 18.10 装配层级全部待确认

常见原因是 Mock 模式、模型调用失败、图纸缺少明确装配证据，或 BOM 行无法和引出序号对应。不要人为填入没有证据的父项；应转人工确认。

### 18.11 审核提示“内容不一致”

复核或批准时页面 JSON 必须与服务端待审快照完全一致。重新单击“加载版本”再核对；如果确实需要修改，由复核人退回，编制人员修改并重新提交。

### 18.12 任务不存在

服务重启会清空内存任务列表，且任务会按保留策略清理。需要长期使用的结果应及时导出；正式审核快照保存在独立 SQLite 文件中。

## 19. 安全与部署建议

1. 涉密图纸只允许发送到批准的内网模型服务；使用云端模型前完成数据分级和授权。
2. 不要在聊天、截图、代码或提交记录中披露 API Key、API Token 和个人复核令牌。
3. 生产环境使用固定、高强度 `ENGINE_BOM_API_TOKEN`，并在反向代理层增加身份认证、TLS、访问日志和速率限制。
4. 限制 `data/` 目录、配置文件和审核数据库的操作系统权限。
5. 对企业规则和关联索引实行版本控制、审批和定期复核。
6. 定期备份审核数据库、人工修正记录和已批准导出；定期演练恢复。
7. 视觉模型输出只作为候选，不自动执行工程更改。
8. 图纸修订副本必须与原文件及审计 JSON 一起保存；原始设计文件不得覆盖。
