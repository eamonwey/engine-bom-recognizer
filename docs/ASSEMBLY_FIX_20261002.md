# 装配父子关系修复与验证记录（2026-10-02）

## 用户无需提供专业标注

本次使用项目中已有、带明确设计答案的合成测试图，由程序比较预测与预期。模型输入只有图纸和前序识别出的 BOM，不提供 expected.json。答案用于推理结束后的评分。

这些是开发回归样例，已用于排查和调整提示词，不是独立盲测集；测试图也未经过独立工程师认证。其结果不能作为真实生产图纸的通用准确率。公开 STEP 装配数据可以验证 CAD 产品结构，但没有相应的已核准二维图纸，不能拿来冒充视觉识别真值。

## 问题与修改

旧流程让模型一次生成整棵树，容易混淆节点编号、明细行和每父用量。旧提示词还将安装关系与 BOM 包含关系混用，并要求总成必须出现在明细行中。共享件在多个子总成中的出现可能丢失；总成只在标题栏出现时也无法表示。

当前默认流程分为：

1. 识别顶层总成身份。读取明确总成件号或工程标题栏，附右下标题栏裁切提高小字可读性。图纸编号不能自动成为已有总成上方的新父件。
2. 提取直接包含关系。使用固定组件引用，逐条记录父件、子件、每父用量、来源页和证据。轴承装在轴上不自动成为“轴包含轴承”。
3. 模型再次查看原图，逐项复核关系、证据和每父用量。它是模型复核，不是人工认证。
4. 程序展开装配树。同一共享件可出现在多个父件下；校验循环、孤立关系、重复冲突和展开上限。
5. 单独核算数量。不能为了让印刷总量正确而删除真实关系或修改每父用量。信息不足显示 incomplete，矛盾报告 ERR-08。

标题栏总成存放在 assembly.context_components，不添加或篡改原始 BOM 行。引用索引对应 BOM 行加标题栏总成的组合列表。前端展示件号、名称、所属父件、层级、用量和证据，并列出无法确认的候选关系。人工保存、导出与评测均支持标题栏总成。

## 代码位置

- `engine_bom/assembly_relations.py`：总成识别、关系提取、模型复核、确定性展开。
- `engine_bom/assembly.py`：层级校验、标题栏总成、数量对账、导出。
- `engine_bom/config.py`：默认 assembly.method=relations；旧 direct 实现保留兼容。
- `engine_bom/webapp.py`：人工保存候选关系、版本和页码校验。
- `static/extensions.js`：父子层级与待核实证据显示。
- `engine_bom/evaluation/tree_metrics.py`：标题栏总成的关系评分。

## 真实模型验证及预期

使用系统现有 qwen3-vl-plus API，经完整 BomPipeline 输入图片/PDF。H 系列详细输出及逐条模型记录见 `data/acceptance/assembly_hierarchy_20260926/results_20261002_121709/`。

该最终运行中 H01–H04 全部通过：每组关系 precision、recall、F1 和每父用量准确率均为1.0；根、节点数、深度、BOM行及预期错误检出也一致。这只是这四个开发样例的结果。

| 样例 | 验证内容 | 预期 |
|---|---|---|
| H01 | 一级装配 | A100 是根；4 个节点、2 层 |
| H02 | 子总成 | A200 下有 S210 与 P220；S210 下有 P211 与 B212；5 个节点、3 层 |
| H03 | 共享件 | B330 分别出现在 S310 和 S320 下；6 行 BOM 展开成7个节点、3层 |
| H04 | 图纸数量错误 | 5 个节点、3层；B412 展开12个、表上11个，报告 ERR-08，保留原印刷值 |
| N01 | 总成只在标题栏 | G100 为根，直属 P1001×1、P1002×1、B16×4；原 BOM 仍为3行 |

N01 图纸：`data/acceptance/gb_reference_20260926/N01.pdf`。两次加入标题栏裁切后的真实调用，父子关系均与上述预期一致，但模型未填出总成基准数量，系统正确保留 quantity=null、quantity_status=incomplete。因此 N01 的关系测试通过，完整数量核算仍未完成，不能标为全功能完全正确。

## 排查中的失败，不隐藏

- 旧 H03 记录重放曾出现关系 F1=0.7273、用量准确率=0.3333。它与本次实时模型配置不一定相同，不作为控制变量下的提升幅度。
- 最初 H04 的复核把“印刷11、展开12”的图纸错误误当成关系错误而删除边，已拆分关系证据与数量对账任务。
- 新增标题栏支持的中间版本曾误建图纸编号父件，或将安装底板作为根。中间 H 系列运行保存在 results_20261002_120958；随后拆分根识别并增加标题栏裁切。
- 早期 N01 调试输出曾被同一路径覆盖，不能称为全部保留；`scripts/check_title_root.py` 现按运行时间分别保存后续结果。

## 如何复查

1. 打开 http://127.0.0.1:8788/ ，按 Ctrl+F5 刷新。
2. 上传 H02.png，查看“装配层级”是否是上表的三层关系。
3. 上传 H03.png，检查 B330 是否同时位于两个子总成下；不能因为件号相同就合并掉一条装配路径。
4. 上传 H04.png，检查 ERR-08 是否同时给出展开12和印刷11；不能静默改成12。
5. 上传 N01.pdf，检查 G100 是否作为标题栏总成出现，原始明细仍为三行。如基准数量没有识别，允许显示数量信息不完整，不应强行通过。

旧任务结果不会自动重新推理，需重新上传后查看新结果。日常使用不要求用户凭专业经验强行确认系统未知的父子关系；未知就是未验证，不能直接当作生产依据。

复跑命令（在项目目录）：

```powershell
python -X utf8 -m unittest discover -s tests -q
python -X utf8 scripts/test_review_fix_browser.py
python -u -X utf8 scripts/run_hierarchy_acceptance.py --cases H01 H02 H03 H04
python -u -X utf8 scripts/check_title_root.py
```

后两条调用配置的真实模型并消耗 API 额度。有限样例通过不保证任意图纸正确；扫描模糊、没有装配表归属、跨页关系和图纸本身缺乏层级信息仍需更广泛的独立样本验证。
